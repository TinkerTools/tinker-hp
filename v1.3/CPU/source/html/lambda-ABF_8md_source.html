3 # Lambda-ABF: Simple, Accurate and Cost-Effective Alchemical Free Energy Computations using Tinker-HP and Colvars
4 
5 Lambda-ABF is an alchemical free-energy method, based on lambda-dynamics, that consists in the following attributes:
6 1. \f$ \lambda \f$ propagation under strongly damped Langevin dynamics with a large mass
7 2. adaptively biased dynamics in $\lambda$ through an ABF (Adaptive Biasing Force) scheme
8 3. efficient sampling (with minimal computational overhead) of orthogonal space with a multiple walker strategy
9 4. free-energy calculation through the TI estimator (in its ABF version)
10 
11 The main benefits of this method lie in its user-friendliness and sampling efficiency. The user protocol for obtaining free-energy estimates is straightforward. The method is supported by the open-source Colvars library, where the alchemical parameter is implemented as new extended variable. This enables the practical manipulation of this coordinate with all the pre-existing functionalities of Colvars, including seamless biasing of this and other coordinates. For Absolute Free Energies of Binding, it can be distance to bound configuration (DBC) collective variable, which facilitates the definition of the bound state and its sampling. [[1,2]](#1,#2)
12 
13 # Tinker-HP input (Keyfile)
14 In order to run Lambda-ABF simulations with Tinker-HP, the user has to add the following lines to its Keyfile (***.key** extension):
15 `lambdadyn` run a lambda-dynamics simulation
16 `ligand -1 5` define the list of atoms whose interactions with the environment will be scaled (typically a ligand). Here it will concern the atoms of index (in the ***.xyz** file) 1 to 5
17 `ligand 1 2 3 4 5` same thing but with explicit list of atoms
18 
19 If one wants to start a simulation from a predefined $\lambda$ value x, one can add:
20 `lambda x`
21 
22 By default, Tinker-HP uses van der Waals **decoupling** (without modifying the intramolecular vdw interactions).
23 To resort to van der Waals **annihilation** (where intramolecular interactions are also scaled down), as done in the Lambda-ABF paper, the following line has to be added to the keyfile.
24 ```vdw-annihilate```
25 
26 **_Lambda-Path_**:
27 The code offers the possibility to scale down the interactions between the "ligand" and the rest of the system by distinguishing between van der Waals and electrostatics (and polarization) interactions.
28 It is done by introducing specific $\lambda$ parameters for each: $\lambda_v$ for van der Waals and $\lambda_e$ for electrostatics. Each of take their value between 0 and 1 and are functions of the "global" $\lambda$ parameters following the definition illustrated below.
29 ![](alch-lambda-path.png)
30 The value (of $\lambda$) at which $\lambda_v$ reaches 1 can be modified by adding the following to the keyfile (here with value 0.5):
31 ``bound-vdw-lambda 0.5
32 ``
33 The value (of $\lambda$) at which $\lambda_e$ reaches 0 can be modified by adding the following to the keyfile (here with value 0.5:
34 ``bound-ele-lambda 0.5
35 ``
36 0.5 is the default value for both these parameters.

39 # Colvars input
40 For lambda-ABF simulations, the user needs to have Colvars linked with Tinker-HP (see Installation), and thus a ***.colvars** file with the same prefix as the one used for the simulation.
41 The $\lambda$ alchemical variable is then defined as an extended variable by putting the following lines in the ***.colvars** file:
42 
43 ```
44 colvar {
45  name l
46  extendedLagrangian on
47  extendedLangevinDamping 1000
48  extendedtemp 300
49  extendedmass 150000
50  lowerBoundary 0.0
51  upperBoundary 0.5
52  #lowerBoundary 0.5
53  #upperBoundary 1.0
54  reflectingLowerBoundary
55  reflectingUpperBoundary
56  width 0.01
57  alchLambda {
58  }
59  outputTotalForce
60  outputAppliedforce
61 }
62 ```
63 Here, the alchemical variable is named l and takes values between 0.0 and 0.5 which would be the van der Waals leg given the default lambda-path (see previous section). Taking values between 0.5 and 1.0 (two commented lines) would then yield the electrostatics leg in the same setup. The damping and the mass sould not be changed (they have been found to give accurate results for a wide range of systems), as well as the width.
64 
65 The temperature should be the target one in Kelvin (here 300K).
66 
67 As an extended collective variable, $\lambda$ (named l in the previous Colvars input) can be used as such in combination with all the features from Colvars (adaptive and fixed bias, combination with other CVs...)[[3]](#3)
68 The time-evolution of $\lambda$ will be printed in the ***.colvars.traj** file.
69 
70 To run Lambda-ABF simulation, one then simply need to add:
71 
72 ```
73 abf {
74  colvars l
75  fullSamples 5000
76 }
77 ```
78 To run Multiple-Walker, this becomes:
79 
80 ```
81 abf {
82  colvars l
83  fullSamples 5000
84  shared
85  sharedfreq 1000
86 }
87 ```
88 To run Multiple-Walker (here with 4 walkers), one needs to add the following line to the keyfile:
89 ```replicas 4
90 ```
91 As with any ABF simulation using Colvars, the estimated PMF as a function of $\lambda$ can be found in the ***.pmf** file that is regularly outputted by Colvars. For Multiple-Walker, it can be found in the ***.all.pmf** file.

94 # Restarting simulations
95 As a collective variable handled by Colvars, the alchemical variable and any (fixed or adaptive) biased simulation involving it can be restarted using a standard ***.state** files regularly outputed by Colvars.
96 (If a **state** file exists with a $\lambda$ value, it will have the priority over any $\lambda$ value defined in the **key** file.)
97 
98 
99 Note that the restarted $\lambda$ must be in accordance with the configuration, taken from a ***dyn** Tinker-HP restart file (when present) or ***xyz** file, and that for this reason care must be taken when choosing the frequency of restart output for Tinker-HP (in the command line) and in Colvars (``colvarsRestartFrequency`` parameter)
100 
101 **Remark for Multiple-Walker simulations:** when restarting Multiple-Walker simulations of a "system" with for example 3 walkers you may have both a global restart: system.dyn and restarts specific to the walkers: system\_reps000.dyn, system\_reps001.dyn, system\_reps002.dyn. The global one always has the priority over the others and if it exists all the walkers will start from it, so make sure to remove it if you want to use the other ones.

103 # Additional Bias with Colvars, example of a DBC variable
104 For Absolute Free Energies of Binding, one needs to add restraints on the disappearing ligand in order to define a binding mode and to make the simulation converge in the weakly coupled regime. Colvars can be used to define all the existing schemes (such as "Boresch" restraints), and also DBC (Distance to Bound Configuration) as done in the Lambda-ABF paper.
105 A DBC collective variable is the RMSD of (a subset of atoms of) the ligand in the moving frame of the binding site.
106 A nice feature of DBC is that can be defined easily by monitoring a regular MD of the complex with the Colvars Dashboard[[4]](#4), and that its free energy contribution can be computed numerically in the gas phase as is done in the SAFEP approach[[5]](#5).
107 
108 
109 The definition of a DBC variable within Colvars typically looks like this (to be added to the Colvars input):
110 
111 ```
112 colvar {
113  name DBC
114 
115  rmsd {
116  # Reference coordinates (for ligand RMSD computation)
117  refPositionsFile alchemy_site.pdb
118 
119  atoms {
120  atomNumbers 1 3 5 7 9 11 12
121 
122  centerReference yes
123  rotateReference yes
124  fittingGroup {
125  atomNumbers 1207 1315 1370 1386 1556 1566 1599 1616 1730 1827
126  }
127  # Reference coordinates for binding site atoms
128  refPositionsFile alchemy_site.pdb
129  }
130  }
131 }
132 ```
