1 # Tinker-HP Suite Overview {#tinker_hp_suite}
2 
3 The Tinker-HP suite is made of 5 main programs that have been designed to run in a High Performance Computing (HPC) context, on GPUs and CPUs, leveraging MPI to run with multiple processes. All of these run based on various **input files** and a **command line**.
4 
5 @subsection common_inputs Common Input Files
6 
7 Some input files are common to all the binaries:
8 
9 - An **xyz** file in the Tinker format representing a **geometry** (through cartesian coordinates), **atom types** of the atoms of the systems as well as their **connectivity**.
10 
11  *Below is an example of an xyz file for a two water molecule system, oxygens are of atom type 101, hydrogens of type 88.*
12 
13 @code{.unparsed}
14  1 O 8.679662 7.087692 -0.696862 101 2 3
15  2 H 7.809455 6.755792 -0.382259 88 1
16  3 H 8.722232 6.814243 -1.617561 88 1
17  4 O -0.117313 8.244447 6.837616 101 5 6
18  5 H 0.216892 7.895445 6.050027 88 4
19  6 H 0.444268 7.826013 7.530196 88 4
20 @endcode
21 
22 - A **keyfile** containing various keywords describing the simulation such as the size of the box, the cutoffs on non-bonded simulations, the integrator for Molecular Dynamics, and also the **parameter file**.
23 
24  *Below is an example of a keyfile for a system using the charmm22 parameter file, with a cubic box size of edge 18.643 Angstroms and the verlet integrator.*
25 
26 @code{.unparsed}
27 parameters charmm22
28 verbose
29 a-axis 18.643
30 integrator verlet
31 @endcode
32 
33 - A **parameter file** listing the parameters, for each atom type, of the force field used for the simulation.

36 @section running_the_programs Running the Programs
37 
38 For all programs of the Tinker-HP suite, the geometry needs to be included in the command line.
39 To further indicate to the programs that the simulation needs to take into account a specific keyfile, the keyfile needs to have the same prefix as the geometry or can be explicitly given in the command line with the prefix `-k keyfile`.
40 
41 *Example of a command line for the analyze binary involving the `watersmall.xyz` geometry and the `watersmall.key` keyfile, on a single MPI process:*
42 
43 @code{.bash}
44 mpirun -np 1 /path/to/analyze watersmall.xyz -k watersmall.key e
45 @endcode
46 
47 The 5 programs are listed below with a description of the command line necessary to run them. In the case of an incomplete command line or a missing input file, an error message describing the missing point will be printed.
48 
49 @section program_analyze analyze
50 Run a single point energy given a trajectory file or a single frame.
51 - **Command line:** `E` as in "Energy decomposition analysis" (see example above)
52 
53 @section program_dynamic dynamic
54 Runs a molecular dynamics trajectory.
55 - **Command line:** A list of arguments has to be passed directly through the command line, respectively:
56  - Number of steps of the desired trajectory
57  - Duration of a timestep (in femtoseconds)
58  - Frequency of output of frames (in picoseconds)
59  - Integer corresponding to the statistical ensemble to be sampled:
60  - `1`: NVE ensemble
61  - `2`: NVT ensemble
62  - `4`: NPT ensemble
63  - Temperature (in Kelvin) for NVT and NPT ensembles
64  - Pressure (in Atmosphere) for NPT ensemble
65 
66 *Example of a command line for the dynamic binary corresponding to 10000 time steps of 1fs in the NPT ensemble at 300K and 1 Atm, with frames printed out every picosecond:*
67 
68 @code{.bash}
69 mpirun -np 1 /path/to/dynamic watersmall.xyz 10000 1 1 4 300 1
70 @endcode
71 
72 > **Note:** More information about the features available with the **dynamic** program, such as integrators, thermostats and barostats, can be found [here](md_dynamic_doxygen.html).
73 
74 @section program_minimize minimize
75 Runs a minimization of the potential energy of a system, starting from a geometry.
76 - **Command line:** Convergence criteria of the minimization algorithm
77 
78 *Example of a command line for the minimize binary corresponding to a convergence threshold of 1 for RMS gradient:*
79 
80 @code{.bash}
81 mpirun -np 1 /path/to/minimize watersmall.xyz 1
82 @endcode
83 
84 > **Note:** The only optimizer is the limited memory BFGS algorithm so no information about the optimizer has to be written in the keyfile. Starting from a *.xyz file, the program will output an addition *.xyz_2 file corresponding to the minimized geometry.
85 
86 @section program_pimd PIMD
87 Runs a Path Integral Molecular Dynamics trajectory to include nuclear quantum effects in the statistics.
88 - **Command line:** The exact same inputs as the one of the **dynamic** programs are necessary in the command line as described above. Several features specific to Path Integral such as the number of beads, as well as other implemented techniques to include nuclear quantum effects (the adaptive Quantum Thermal Bath) can be found in `Quantum-HP.md`.
89 
90 @section program_bar bar
91 Compute free energy differences through the Bennett Acceptance Ratio estimator. In Tinker-HP, free energy differences are obtained in a post-processing step, in two stages. Given two keyfiles and two trajectories associated to two hamiltonians, first a `.bar` file is produced with, for each trajectory, the potential energies associated to the two hamiltonians. Then, given the `.bar` file, one can run the self-consistent procedure to get the final free energy difference through the bar estimator.
92 
93 - **Command line:**
94  - `1` to generate the `.bar` file, `2` to post-process it to get the bar estimation.
95  - For generation of the bar file, one has to indicate the two geometries with their keyfiles and the two temperatures.
96 
97 *Example of a command line for the bar binary to generate the `.bar` file corresponding to systema at temperature tempa and systemb at temperature tempb:*
98 
99 @code{.bash}
100 mpirun -np 1 /path/to/bar 1 systema.xyz -k systema.key 300 systemb.xyz -k systemb.key 300
101 @endcode
102 
103 - For estimation of the free energy difference, one has to indicate the bar file.
104 
105 *Example of a command line for the bar binary to get the free energy estimation based on the `system.bar` file:*
106 
107 @code{.bash}
108 mpirun -np 1 /path/to/bar 2 system.bar
109 @endcode
110 
111 @section program_testgrad testgrad
112 Compute gradients associated with a geometry. One can compute analytical gradients of the potential energy terms or numerical ones, on all the cartesian degrees of freedom.
113 - **Command line:**
114  - `Y` to compute analytical gradients, `N` if it is not the case
115  - `Y` to compute numerical gradients (through finite differences), `N` if not
116  - When numerical gradients are requested, size of the step displacement in Angstroms
117  - `Y` if breakdown by component is requested, `N` if not
118

121 @section general_information General Information
122 
123 - Tinker-HP is compatible with numerous bonded and non-bonded potential energy terms. For each of them, energies and analyticals gradients can be computed by running the programs described above.
124  Each of them is associated with a number of features that can be modified by some keywords to be added to the keyfile.
125  A list of these potential energy terms with associated keywords can be found [here](md_potential_doxygen.html).
126 - Informations about I/O can be found [here](md_io_doxygen.html)
127 - Info about free energy simulations can be found [here](md_free_energy.html), with specifics about alchemical ones through Lambda-ABF and related methodologies [here](md_lambda-abf_doxygen.html)
