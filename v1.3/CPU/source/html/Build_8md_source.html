2 
3 ## Calculation Libraries
4 
5 Tinker-HP requires the <span class="smallcaps">mkl</span> library, a FFT
6 library (such as <span class="smallcaps">fftw</span>) and a slightly
7 modified <span class="smallcaps">2decomp_fft</span> library (shipped
8 with Tinker-HP) in order to run. The
9 <span class="smallcaps">2decomp_fft</span> library enables parallel 3D
10 <span class="smallcaps">fft</span> computations based on 2d-pencils data
11 distribution (see
12 [<span class="smallcaps">2decomp_fft</span> site](http://www.2decomp.org))
13 based on a sequential implementation of
14 <span class="smallcaps">FFTs</span> such as the one provided by the
15 <span class="smallcaps">fftw</span> library.
16 
17 ## Parallel library
18 
19 Tinker-HP also requires a recent enough
20 <span class="smallcaps">mpi</span> library supporting
21 <span class="smallcaps">mpi</span> 3.x standards such as non blocking
22 collectives. The code has been extensively tested with recent
23 Intel<span class="smallcaps">mpi</span> versions (such as intel
24 <span class="smallcaps">mpi</span> 5.1) and better performances have
25 been observed with this family of
26 <span class="smallcaps">mpi</span> implementation compared to other ones
27 such as Open<span class="smallcaps">mpi</span> .

29 # Installation
30 
31 As Tinker-HP is shipped in source form, you need to compile it. This was
32 not always an easy task in the previous releases. Tinker-HP now uses a
33 `configure` script built with autotools packages from
34 <span class="smallcaps">Gnu</span> to ease the compilation and
35 installation process. The first thing you should do is to type :
36 
37 `autoconf ; automake `
38 
39 in the main directory. This will generate the `configure` file. Apart
40 from the usual options available with all `configure` scripts, there are
41 specific options for Tinker-HP.
42 
43  Usage: ./configure [OPTION]... [VAR=VALUE]...
44 
45  Optional Features:
46  --enable-debug Enable debug mode (check array bounds, implicit
47  none, etc...). Should not be active in normal
48  operations [default is no]
49  --enable-skylake Enable AVX512 Optimization for Skylake Processors
50  [default is no]
51  --enable-knl Enable AVX512 Optimization for KNL (Xeon Phi)
52  Processors [default is no]
53  --enable-fft-generic Enable generic FFT mode [default is yes]
54  --enable-fft-mkl Enable MKL FFT mode [default is no]
55  --enable-fft-fftw3 Enable fftw3 FFT mode [default is no]
56  --enable-fft-fftw3_f03 Enable fftw3_f03 FFT mode [default is no]
57  --enable-plumed Enable plumed interface [default is no]
58  --enable-colvars Enable Colvars interface [default is no]
59  Optional Packages:
60  --with-blaslib=<BLAS LIB> Specify BLAS library [mkl, lapack or
61  /absolute/path/to/BLAS_library]
62  --with-fftlib=<FFT LIB> Specify a library for FFT called by 2decomp [mkl or
63  fftw3 or /absolute/path/to/FFTW_library]
64 
65 The ultimate goal of this script is to let you type
66 
67  ./configure ; make ; make install ; cd example ; ./ubiquitin2.run
68 
69 and have everything compiled, installed and running.

71 ## List of Options
72 
73 As for all the `configure` scripts, you can choose the directory in
74 which the binaries will be copied. So, `configure` has `--prefix=<DIR>`.
75 
76 Tinker-HP has a special interest to know if it will run on AVX-512
77 capable processors. So, `configure` has options for that:
78 
79 - `--enable-slylake`
80 
81 - `--enable-knl`
82 
83 Recall that Tinker-HP needs to make a
84 <span class="smallcaps">fft</span> decomposition with a modified version
85 of the <span class="smallcaps">2decomp_fft</span> library, which in turn
86 needs a working <span class="smallcaps">fftw</span> library. This is why
87 you can find `configure` options about
88 <span class="smallcaps">fft</span> interface and library:
89 
90 - `--enable-fft-generic`
91 
92 - `--enable-fft-mkl`
93 
94 - `--enable-fft-fftw3`
95 
96 - `--enable-fft-fftw3_f03`
97 
98 - `--with-fftlib=``<FFT LIB>`
99 
100 Tinker-HP also needs some functions that resides in a working
101 <span class="smallcaps">blas</span> library. So, there is an option for
102 that:
103 
104 - `--with-blaslib=``<BLAS LIB>`
105 
106 Tinker-HP is now able to be interfaced with
107 <span class="smallcaps">Plumed</span>. So, there is an option for that :
108 
109 - `--enable-plumed`
110 
111 Tinker-HP is now able to be interfaced with
112 <span class="smallcaps">Colvars</span>. So, there is an option for that
113 :
114 
115 - `--enable-colvars`
116 
117 Finally, as there might be some execution problems, or compilation
118 problems for the users who develop code, Tinker-HP has an
119 `--enable-debug` option.
120 
121 `configure` tries to find its path to reach a valid
122 <span class="smallcaps">mpi</span> compiler and a valid Fortran compiler
123 by unsetting the environment variables `$FC` and `$F77`, and reading the
124 environment variable `$PATH`. It also tries to find valid
125 <span class="smallcaps">fft</span> and
126 <span class="smallcaps">blas</span> libraries by reading `$FFTW` and
127 `$MKLROOT` or `$LAPACK` respectively. Most of the time, these
128 environment variables are defined through the `module` framework. As a
129 try, do a
130 
131  module available 2>&1 | less
132 
133 to see if you have the `module` framework installed on your machine, and
134 to know what `module` you can load. `configure` then figures out how to
135 build the correct Makefiles.
136 
137 By default, `configure` chooses the
138 <span class="smallcaps">mkl</span> library from Intel as the
139 <span class="smallcaps">blas</span> and
140 <span class="smallcaps">fftw3</span> libraries, sets the
141 `--enable-fft-mkl` option, does not make any processor optimization, and
142 disables debugging. Thus, typing `./``configure` give the same result as
143 if you have typed
144 `./``configure` `--enable-fft-mkl` `--with-blaslib=``mkl` `--with-fftlib=``mkl`.

146 ## Using `configure`
147 
148 If you want to have different settings than those used by default,
149 you’ll have to give `configure` more information. Be aware that
150 `configure` cannot magically guess anything. So, the information you
151 give must be precise and complete.

153 ### Install Directory
154 
155 By default, this is where you have unzipped and untarred the
156 distribution. If you want another place, use `--prefix=<DIR>`. You can
157 choose any directory you want, providing that you have permission to
158 create this directory and/or write in it.

160 ### Processor optimization
161 
162 The machine on which you compile is not always the one on which
163 Tinker-HP will run. If you know that Tinker-HP is going to run on
164 AVX-512 capable processors, you are strongly encouraged to use one of :
165 
166 - for KNL processors (also known as Xeon-Phi)
167 
168 - for Skylake processors.
169 
170 as this will dramatically improve the execution speed. Otherwise, the
171 optimization will be done using the capabilities of the compilation
172 machine, as determined by the compiler.

293 ### DEBUG mode
294 
295 This mode is primarily intended for developers, but can also be useful
296 if you experience errors while running Tinker-HP. Adding
297 `--enable-debug` to the `configure` command turns on **boundary
298 checking**, forces **implicit none**, sets the optimization level to
299 **0** (the lowest value) and enables **backtracing** and **all
300 warnings**. The compilation produces all the binaries and gives them the
301 `.debug` extension, so that you know that these binaries are not
302 optimized.

362 ## Making binaries
363 
364 Once you are happy with the option you selected, it’s time to run the
365 `make` command, or even the `make install` command, which will compile
366 and install all at once.
367 
368 As the compilation process takes care of the dependencies between
369 subroutines and modules, you can safely use the `-j` flag of the `make`
370 command to do parallel compilation. This would dramatically speedup the
371 compilation process.
372 
373 Anyway, on modern machines, the compilation is not very long, except for
374 2 or 3 subroutines that can take up to 5(!) minutes to compile,
375 depending on the compiler you use and even on the fastest machines.
376 Everything should compile and link gracefully.
377 
378 Using `make install` will copy the binaries into the directory you
379 selected with the `--prefix=<DIR>` option. The binaries produced will
380 have the following extension :
381 
382 <div class="center">
383 
384 | Mode | Extension |
385 |:-----------------|:----------------|
386 | `NORMAL` | .prod |
387 | `PLUMED NORMAL` | \_plumed.prod |
388 | `COLVARS NORMAL` | \_colvars.prod |
389 | `DEBUG` | .debug |
390 | `PLUMED DEBUG` | \_plumed.debug |
391 | `COLVARS DEBUG` | \_colvars.debug |
392 
393 </div>
394 
395 the `make install` command will also create 5 shell scripts, named after
396 the binaries, to setup the proper running environment. Don’t forget to
397 install the binaries you created, or you will not be able to run the
398 examples.

400 # Note for developers
401 
402 ## Writing new sources
403 
404 We don’t want to impose you a unique style of writing. Indeed, we don’t
405 have one. But we just want to give you some rules we believe are
406 important for the consistency of Tinker-HP’s code.
407 
408 #### File format
409 
410 We use <span class="smallcaps">Fixed Form</span> format throughout all
411 the code, even though the code is written in
412 <span class="smallcaps">Fortran90</span>. This is mandatory. The
413 compilation process would not work otherwise.
414 
415 #### Editing
416 
417 We always use lowercase letters for code (except for printing purposes).
418 We indent all lines embedded in `do.....enddo`, `do.....while`, etc...
419 statements, or in `if...else...endif` constructs.
420 
421 #### Variable declarations
422 
423 You are required to use `implicit none`. If you compile in debug mode,
424 that will be enforced by the compiler.
425 
426 The order we use to declare variables is:
427 
428 1. `integer` (4 bytes sized)
429 
430 2. `real` (8 bytes sized)
431 
432 3. `logical`
433 
434 4. `array` (in the same order)
435 
436 5. `character` (single string or array)
437 
438 We always try not to mix different types of variables in the same
439 declaration line. This is not just because it is easier to read. That is
440 also because it is more memory efficient, particularly for
441 vectorization, where alignment in memory is crucial. `character`
442 variables should be put at the very end, since they can have arbitrary
443 lengths and almost never align to a memory boundary. We also try to
444 choose significant names for the variables.
445 
446 #### Comments
447 
448 We always begin a comment line by the `c` character. The `!` character
449 should only appear in the middle of a line. This is because the `!`
450 character at the beginning is reserved to introduce compiler directives.
451 
452 If ever you create modules, please comment all the new variables you
453 create, like :
454 
455  c maxvalue atoms directly bonded to an atom
456  c maxgrp user-defined groups of atoms
457  c maxtyp force field atom type definitions
458  c maxclass force field atom class definitions
459 
460 In subroutines or functions, give as many comments as you believe is
461 needed to understand what your code is doing. That would be precious for
462 you, and for us as well.
463 
464 ## Compiling new sources
465 
466 If you make development on Tinker-HP, it is likely that you would need
467 to add subroutines and modules in the source directory.
468 
469 All modules should be put in files named `MOD_xxxxx.f`, even though they
470 are written in <span class="smallcaps">Fortran90</span>. All functions
471 and routines should be put in files with names beginning by a lowercase
472 letter and with `.f` extension. Please, try to find significant names (
473 `epolar1tcg2shortreal.f` is far better than `ep1tc2shre.f`). You are
474 required to follow this scheme as much as possible.
475 
476 To compile your new sources, you should add them in the `Makefile.am`
477 file of the `source` directory. We’ve put some comments in this file, to
478 help you know where to put things. Search for the string `Add` in the
479 file.
480 
481 There are 3 different cases[^1]:
482 
483 1. You created a new main program (like `analyze` or `dynamic`). Add a
484  line
485 
486  `bin_PROGRAMS += yourmain`
487 
488  (with no extension) below the line `bin_PROGRAMS += testgrad`. Then,
489  add the lines
490 
491  `yourmain_SOURCES = yourmain.f`
492 
493  and
494 
495  `yourmain_DEPENDENCIES = libtinkermod.a libtinkercalc.a `
496 
497  after the similar lines concerning `testgrad`.
498 
499  In the `Makefile.am` file of the `scripts` directory, you should
500  also add the line :
501 
502  `-(cd $``bindir`` ; $(LN_S) -f $(LINK_TO) yourmain )`
503 
504  in the `install-exec-hook:` section, and add `yourmain` at the end
505  of the `uninstall-binSCRIPTS:` section.
506 
507 2. You created new module(s). Add lines
508 
509  `libtinkermod_a_SOURCES += MOD_xxxxx.f`
510 
511  just below[^2] `libtinkermod_a_SOURCES += MOD_virial.f`
512 
513 3. You created functions and subroutines. Add lines like
514 
515  `libtinkercalc_a_SOURCES += yourexplicitfilename.f`
516 
517  just below[^3] the line `libtinkercalc_a_SOURCES += version.f`
518 
519 You should now go in the main directory, where `configure.ac` resides,
520 and type `autoconf` and `automake`. `autoconf` should not generate any
521 message. `automake` will probably do, mainly because of a different
522 version than the one we used to create the distribution. In this case,
523 just type `aclocal` before running `automake` again. These 2 (or 3)
524 commands will generate a new `configure` script that takes care of your
525 new sources. You should then run `./``configure`[^4], compile, install
526 and enjoy debugging your code.

528 # Executables
529 
530 After having successfully compiled the code, five executable files
531 should be present in the install directory: `analyze`, `bar`, `dynamic`,
532 `testgrad` and `minimize`[^5], which are the analogous of the binaries
533 of the Tinker-8.4 release and require similarly a geometry (given by a
534 \*.xyz file), a simulation setup (given by a \*.key file) and possibly a
535 restart (given by a \*.dyn file) for the `dynamic` program.
536 
537 All these executables must run in the same environment you had during
538 the compilation phase. That means the same set of modules, or the
539 correct `LIBRARY_PATH`. They should be launched with the
540 `mpirun -np `` x` prefix in order to run in parallel with `x`
541 <span class="smallcaps">mpi</span> processes.
542 
543 ## General remarks
544 
545 The only boundary conditions that are available in this release are
546 periodic boundary conditions treated with Particle Mesh Ewald.
547 General triclinic unit cells can be used.
548 
549 Classical force fields such as AMBER, CHARMM and OPLS are available in
550 Tinker-HP as well as polarizable force fields such as AMOEBA, AMOEBA+ and HIPPO.
551 
552 ## `analyze` 
553 
554 The `analyze` executable allows potential energy analysis. Compared to
555 the Tinker-8.4 software, the only option compatible with this binary is
556 "e".
557 
558 For example the command line:
559 
560 - `mpirun -np`` 16 ../bin/analyze dhfr2 e`\
561  will give you as an output the potential energy terms of the geometry
562  given by a dhfr2.xyz file and with the simulation setup given by the
563  dhfr2.key file. Furthermore, this computation will run on 16
564  <span class="smallcaps">mpi</span> processes.
565 
566 ## `testgrad` 
567 
568 The `testgrad` program is absolutely equivalent to the one of the
569 Tinker-8.4 release: it allows the output of the components of the
570 analytical and/or numerical gradients of the different energy terms.
571 
572 For example, the command line:
573 
574 - `mpirun -np`` 16 ../bin/testgrad dhfr2 Y Y 0.0001 Y`\
575  will give you as an output all the analytical and numerical gradients
576  (computed with an increment of 0.0001 Angstroms for the positions of
577  the atoms) of all the energy terms of the dhfr2 system.
578 
579 ## `minimize`
580 
581 The `minimize` program computes energy minimization starting from a
582 given structure, using a low memory quasi-newton BFGS algorithm as in
583 Tinker-8.4. The command line used should give the numerical threshold
584 for the convergence of the algorithm.
585 
586 For example, the command line:
587 
588 - `mpirun -np`` 16 ../bin/minimize dhfr2 0.1`\
589  will compute energy minimization on the dhfr2 structure until the RMS
590  on the gradient is inferior to 0.1. The new geometry will be written
