1 The Tinker-HP suite is made of 5 main programs that have been designed to run in a High Performance Computing (HPC) context, on GPUs and CPUs, leveraging MPI to run with multiple processes. All of these run based on various **input files** and a **command line**.
2 Some input files are common to all the binaries:
3 1. an **xyz** file in the Tinker format representing a **geometry** (through cartesian coordinates), **atom types** of the atoms of the systems as well as their **connectivity**.
4 
5 *Below is an example of xyz file for a two water molecule system, oxygens are of atom type 101, hydrogens of type 88.*
6 
7 ```
8  1 O 8.679662 7.087692 -0.696862 101 2 3
9  2 H 7.809455 6.755792 -0.382259 88 1
10  3 H 8.722232 6.814243 -1.617561 88 1
11  4 O -0.117313 8.244447 6.837616 101 5 6
12  5 H 0.216892 7.895445 6.050027 88 4
13  6 H 0.444268 7.826013 7.530196 88 4
14 ```
15 
16 2. a **keyfile** containing various keywords describing the simulation such as the size of the box, the cutoffs on non-bonded simulations, the integrator for Molecular Dynamics, and also the **parameter file**
17 
18 *Below is an example of keyfile for a system using the charmm22 parameter file, with a cubic box size of edge 18.643 Angstroms and the verlet integrator.*
19 
20 ```
21 parameters charmm22
22 verbose
23 a-axis 18.643
24 integrator verlet
25 ```
26 
27 3. a **parameter file** listing the parameters, for each atom type, of the force field used for the simulation.
28 
29 For all programs of the Tinker-HP suite, the geometry needs to be included in the command line.
30 To further indicate the programs that the simulation needs to take into account a specific keyfile, the keyfile needs to have the same prefix as the geometry or can be explicitely given in the command line with the prefix "-k keyfile".
31 
32 *Example of a command line for the analyze binary involving the watersmall.xyz geometry and the watersmall.key keyfile, on a single MPI process*
33 
34 ```
35 mpirun -np 1 analyze watersmall.xyz -k watersmall.key e
36 ```

38 The 5 programs are listed below with a description of the command line necessary to run them. In the case of an incomplete command line or a missing input file an error message describing the missing point will be printed.
39 
40 
41 
42 1. **analyze**: run single point energy given a trajectory file or a single frame.
43  - _command line_: E as in "Energy decomposition analysis" (see example above)
44 
45 2. **dynamic**: runs a molecular dynamics trajectory
46  - command line: a list of arguments has to be passed directly through the command line, respectively:
47  - number of steps of the desired trajectory
48  - duration of a timestep (in femtoseconds)
49  - frequency of output of frames (in picoseconds)
50  - integer corresponding to the statistical ensemble to be sampled:
51  - 1: NVE ensemble
52  - 2: NVT ensemble
53  - 4: NPT ensemble
54  - temperature (in Kelvin) for NVT and NPT ensembles
55  - pressure (in Atmosphere) for NPT ensemble
56 
57  *Example of a command line for the dynamic binary corresponding to 10000 time steps of 1fs in the NPT ensemble at 300K and 1 Atm, with frames printed out every picoseconds:*
58 
59 ```
60 mpirun -np 1 dynamic watersmall.xyz 10000 1 1 4 300 1
61 ```
62 
63 More information about the features available with the **dynamic** program, such as integrators, thermostats and barostats, can be found here.
64 
65 3. **minimize**: runs a minimization of the potential energy of a system, starting from a geometry.
66  - _command line_: convergence criteria of the minimization algorithm
67 
68 *Example of a command line for the minimize binary corresponding to a convergence threshold of 1 for RMS gradient:*
69 
70 ```
71 mpirun -np 1 minimize watersmall.xyz 1
72 ```
73 
74 More information about the features available with the **minimize** program, such as minimization algorithms and minimized geometry output can be found here.
75 
76 4. **PIMD**: runs a Path Integral Molecular Dynamics trajectory to include nuclear quantum effects in the statistics.
77  - _command line_: the exact same inputs as the one of the **dynamic** programs are necessary in the command line as described above. Several features specific to Path Integral such as the number of beads, as well as other implemented techniques to include nuclear quantum effects (the adaptive Quantum Thermal Bath) can be found in Quantum-HP.md.
78 
79 5. **bar**: compute free energy differences through the Bennett Acceptance Ratio estimator. In Tinker-HP, free energy differences are obtained in a post-processing step, in two stages. Given two keyfiles and two trajectories associated to two hamiltonians, first a *.bar file is produced with, for each trajectory, the potential energies associated to the two hamiltonians. Then, given the .bar file, one can run the self consistent procedure to get the final free energy difference through the bar estimator.
80 
81  - _command line_:
82  - 1 to generate the .bar file, 2 to post-process it to get the bar estimation
83  - for generation of the bar file, one has to indicate the two geometries with their keyfiles and the two temperatures
84 
85  *Example of a command line for the bar binary to generate the .bar file corresponding to systema at temperature tempa and systemb at temperature tempb*
86 
87 ```
88 mpirun -np 1 bar 1 systema.xyz -k systema.key 300 systemb.xyz -k systemb.key 300
89 ```
90 
91 - for estimation of the free energy difference, one has to indicate the bar file
92 
93  *Example of a command line for the bar binary to get the free energy estimation based on the system.bar file*
94 
95 ```
96 mpirun -np 1 bar 2 system.bar
97 ```
98 
99 
100 6. **testgrad**: compute gradients associated with a geometry. One can compute analytical gradients of the potential energy terms or numerical ones, on all the cartesian degrees of freedom.
101  - _command line_:
102  - Y to compute analytical gradients, N if it is not the case
103  - Y to compute numerical gradients (through finite differences), N if not
104  - when numerical gradients are requested, size of the step displacement in Angstroms
105  - Y if breakdown by component is requested, N if not
