1 # Lambda-ABF: Simple, Accurate and Cost-Effective Alchemical Free Energy Computations using Tinker-HP and Colvars {#lambda_abf}
2 
3 <a href="https://doi.org/10.1021/acs.jctc.3c01249">
4  <img src="https://zenodo.org/badge/DOI/10.1021/acs.jctc.3c01249.svg" alt="DOI:10.1021/acs.jctc.3c01249">
5 </a>
6 
7 Lambda-ABF is an alchemical free-energy method, based on lambda-dynamics, that consists of the following attributes:
8 
9 1. \f$ \lambda \f$ propagation under strongly damped Langevin dynamics with a large mass.
10 2. Adaptively biased dynamics in \f$ \lambda \f$ through an ABF (Adaptive Biasing Force) scheme.
11 3. Efficient sampling (with minimal computational overhead) of orthogonal space with a multiple walker strategy.
12 4. Free-energy calculation through the TI estimator (in its ABF version).
13 
14 The main benefits of this method lie in its user-friendliness and sampling efficiency. The user protocol for obtaining free-energy estimates is straightforward. The method is supported by the open-source Colvars library, where the alchemical parameter is implemented as a new extended variable. This enables the practical manipulation of this coordinate with all the pre-existing functionalities of Colvars, including seamless biasing of this and other coordinates. For Absolute Free Energies of Binding, it can be a distance to bound configuration (DBC) collective variable, which facilitates the definition of the bound state and its sampling. [[1,2]](#ref1)

18 ## Tinker-HP Input (Keyfile) {#tinker-hp-input}
19 
20 In order to run Lambda-ABF simulations with Tinker-HP, the user has to add specific lines to their Keyfile (`*.key` extension):
21 
22 * `lambdadyn`: Run a lambda-dynamics simulation.
23 * `ligand -1 5`: Define the list of atoms whose interactions with the environment will be scaled (typically a ligand). Here it will concern the atoms of index (in the `*.xyz` file) 1 to 5.
24 * `ligand 1 2 3 4 5`: Same thing but with an explicit list of atoms.
25 
26 If one wants to start a simulation from a predefined \f$ \lambda \f$ value `x`, one can add:
27 @code{.unparsed}
28 lambda x
29 @endcode
30 
31 By default, Tinker-HP uses van der Waals **decoupling** (without modifying the intramolecular vdw interactions).
32 To resort to van der Waals **annihilation** (where intramolecular interactions are also scaled down), as done in the Lambda-ABF paper, the following line has to be added to the keyfile:
33 @code{.unparsed}
34 vdw-annihilate
35 @endcode
36 
37 ### Lambda-Path
38 
39 The code offers the possibility to scale down the interactions between the "ligand" and the rest of the system by distinguishing between van der Waals and electrostatics (and polarization) interactions.
40 
41 It is done by introducing specific \f$ \lambda \f$ parameters for each: \f$ \lambda_v \f$ for van der Waals and \f$ \lambda_e \f$ for electrostatics. Each takes a value between 0 and 1 and are functions of the "global" \f$ \lambda \f$ parameter following the definition illustrated below.
42 
43 <img src="alch-lambda-path.png" alt="Lambda-Path separating van der Waals and electrostatics" width="600"/>
44 
45 The value (of \f$ \lambda \f$ ) at which \f$ \lambda_v \f$ reaches 1 can be modified by adding the following to the keyfile (here with a value of 0.5):
46 @code{.unparsed}
47 bound-vdw-lambda 0.5
48 @endcode
49 
50 The value (of \f$ \lambda \f$ ) at which \f$ \lambda_e \f$ reaches 0 can be modified by adding the following to the keyfile (here with a value of 0.5):
51 @code{.unparsed}
52 bound-ele-lambda 0.5
53 @endcode
54 
55 > **Note:** `0.5` is the default value for both of these parameters.

59 ## Colvars Input {#colvars-input}
60 
61 For lambda-ABF simulations, the user needs to have Colvars linked with Tinker-HP (see Installation), and thus a `*.colvars` file with the same prefix as the one used for the simulation.
62 
63 The \f$ \lambda \f$ alchemical variable is then defined as an extended variable by putting the following lines in the `*.colvars` file:
64 
65 @code{.tcl}
66 colvar {
67  name l
68  extendedLagrangian on
69  extendedLangevinDamping 1000
70  extendedtemp 300
71  extendedmass 150000
72  lowerBoundary 0.0
73  upperBoundary 0.5
74  #lowerBoundary 0.5
75  #upperBoundary 1.0
76  reflectingLowerBoundary
77  reflectingUpperBoundary
78  width 0.01
79  alchLambda {
80  }
81  outputTotalForce
82  outputAppliedforce
83  subtractAppliedForce
84 }
85 @endcode
86 
87 Here, the alchemical variable is named `l` and takes values between 0.0 and 0.5, which would be the van der Waals leg given the default lambda-path (see previous section). Taking values between 0.5 and 1.0 (two commented lines) would then yield the electrostatics leg in the same setup. The damping and the mass should not be changed (they have been found to give accurate results for a wide range of systems), as well as the width.
88 
89 The temperature should be the target one in Kelvin (here `300`).
90 
91 As an extended collective variable, \f$ \lambda \f$ (named `l` in the previous Colvars input) can be used as such in combination with all the features from Colvars (adaptive and fixed bias, combination with other CVs...). [[3]](#ref3) The time-evolution of \f$ \lambda \f$ will be printed in the `*.colvars.traj` file.
92 
93 To run a Lambda-ABF simulation, one then simply needs to add:
94 @code{.tcl}
95 abf {
96  colvars l
97  fullSamples 5000
98 }
99 @endcode
100 
101 To run a Lambda-ABF-OPES simulation, one then simply needs to add:
102 @code{.tcl}
103 opes_metad {
104  name opes_l
105  colvars l
106  newHillFrequency 300
107  barrier 5
108  adaptiveSigma on
109  neighborList on
110  printTrajectoryFrequency 1000
111  pmf on
112  pmfColvars l
113  pmfHistoryFrequency 1000
114  outputEnergy on
115  explore on
116 }
117 @endcode
118 
119 To run Multiple-Walker, this becomes:
120 @code{.tcl}
121 abf {
122  colvars l
123  fullSamples 5000
124  shared
125  sharedfreq 1000
126 }
127 @endcode
128 
129 To run Multiple-Walker (here with 4 walkers), one needs to add the following line to the keyfile:
130 @code{.unparsed}
131 replicas 4
132 @endcode
133 
134 As with any ABF simulation using Colvars, the estimated PMF as a function of \f$ \lambda \f$ can be found in the `*.pmf` file that is regularly outputted by Colvars. For Multiple-Walker, it can be found in the `*.all.pmf` file.

138 ## Restarting Simulations {#restarting-simulations}
139 
140 As a collective variable handled by Colvars, the alchemical variable and any (fixed or adaptive) biased simulation involving it can be restarted using standard `*.state` files regularly outputted by Colvars.
141 *(If a state file exists with a \f$ \lambda \f$ value, it will have priority over any \f$ \lambda \f$ value defined in the key file.)*
142 
143 Note that the restarted \f$ \lambda \f$ must be in accordance with the configuration, taken from a `*.dyn` Tinker-HP restart file (when present) or `*.xyz` file. For this reason, care must be taken when choosing the frequency of restart output for Tinker-HP (in the command line) and in Colvars (`colvarsRestartFrequency` parameter).
144 
145 > **Remark for Multiple-Walker simulations:** When restarting Multiple-Walker simulations of a "system" with, for example, 3 walkers, you may have both a global restart (`system.dyn`) and restarts specific to the walkers (`system_reps000.dyn`, `system_reps001.dyn`, `system_reps002.dyn`). The global one always has priority over the others, and if it exists all the walkers will start from it. Make sure to remove it if you want to use the other ones.

149 ## Additional Bias with Colvars (Example of a DBC Variable) {#additional-bias}
150 
151 For Absolute Free Energies of Binding, one needs to add restraints on the disappearing ligand in order to define a binding mode and to make the simulation converge in the weakly coupled regime. Colvars can be used to define all the existing schemes (such as "Boresch" restraints), and also DBC (Distance to Bound Configuration) as done in the Lambda-ABF paper.
152 
153 A DBC collective variable is the RMSD of (a subset of atoms of) the ligand in the moving frame of the binding site. A nice feature of DBC is that it can be defined easily by monitoring a regular MD of the complex with the Colvars Dashboard [[4]](#ref4), and its free energy contribution can be computed numerically in the gas phase as is done in the SAFEP approach [[5]](#ref5).
154 
155 The definition of a DBC variable within Colvars typically looks like this (to be added to the Colvars input):
156 
157 @code{.tcl}
158 colvar {
159  name DBC
160 
161  rmsd {
162  # Reference coordinates (for ligand RMSD computation)
163  refPositionsFile alchemy_site.pdb
164 
165  atoms {
166  atomNumbers 1 3 5 7 9 11 12
167 
168  centerReference yes
169  rotateReference yes
170  fittingGroup {
171  atomNumbers 1207 1315 1370 1386 1556 1566 1599 1616 1730 1827
172  }
173  # Reference coordinates for binding site atoms
174  refPositionsFile alchemy_site.pdb
175  }
176  }
177 }
178 @endcode
