3 ## Direct Build
4 For most users, we recommend this relatively accessible method which lies on a bash installation script named `/tinker-hp/GPU/ci/install/sh`. After setting your environment according to the @ref prerequisites "Prerequisites", change directory to the GPU folder, edit the configuration section of the installation script to select your build and proceed with the commands below.
5 
6 @code{.sh}
7 $> pwd
8 #> /home/$user/.../tinker-hp/GPU
9 $> ./ci/install.sh
10 @endcode
11 
12 This script will create and install two types of binaries for every applications. Double and mixed precision program will be available by the end of the installation, in the installdir.
13 As long as you stand for one configuration at the time, The installation script will serve as an ideal build assistant. In the event of the installation script failure, we recommend to follow one the procedures given below.
14 
15 ### Configuration
16 The configuration section of `ci/install.sh` lists some variables which are passed to the Makefile during the compiling stage. Edit this part according to your need, before executing the script. We keep this section updated as the development progresses.
17  - `dbuild` for out-of-source build. If interested in an other configuration without losing the previous object files, you may use a different value like `$tinkerdir/build1`
18  - `target_arch` control the target platform architecture. Decide whether the build should target CPUs or GPUs
19  - `c_c` Stand for compute capability. It is specific to the GPU device. Default option target every Nvidia GPU from Pascal architecture to Ampere.
20  - `build_plumed` (switch) enables/disables *PLUMED* interface. PLUMED is automatically built
21  - `build_colvars` (switch) enables/disables *COLVARS* interface. COLVAR is automatically built
22  - `NN` (switch) enables/disables Neural Network python interface.
23  - `FPA` (switch) enables/disables fixed precision arithmetic in mixed precision (enabled by default)
24 
25 @warning Requires a CUDA python environment consistent with the installation one before building.
26 
27 ## Using Makefile
28 This part concerns every developers or anyone familiar enough with source code compilation. `GPU/source/Makefile.pgi` allows every type of build. By editing configurations variables you can change default compilers, adapts flags, rename libraries, and so on. Here is the description of the useful variables need to configure your own build's.
29 
30 ### Configuration variables
31  - `NVTX_SUPPORT` enables NVTX markers during profiling if set to 1. This option is not useful in release construct.
32  - `NVSHMEM_SUPPORT` enables build with nvshmem library if set to 1. This option requires `NVSHMEM_HOME` variable to be set on nvshmem install directory. It has not been tested with recent Nvidia HPC package.
33  - `NO_MUTATION` disables soft-core computation if set to 1
34  - `FPA_SUPPORT` enables fixed point arithmetic in non-Bonded Forces and energy reduction if set to 1. It requires mixed precision to be enabled through the Makefile precision variable.
35  - `PLUMED_SUPPORT` builds and link both Tinker-HP and Plumed Package supplied next to it.
36  - `NN_SUPPORT` builds, interfaces and links Tinker-HP with machine learning code
37  - `arch=(host|[device]) .or. (cpu|[gpu])` allows you to select target architecture
38  - `prec=(single|mixed|[double]) .or. (s|m|[d])` changes the precision build
39  - `prefix=(path/|[../bin])` controls the installation directory
40  - `prog_suffix=(any_string|[])` append suffix to install binary. This variable may allow you to have multiple binaries in the installation directory.
41  For instance `analyze` or `analyze.gpu`
42  - `compute_capability=(list|[60,70])` selects the device's compute capability for the construct. this variable shall accept a list of compute capability separated by a comma.
43  e.g. `compute_capability=35,60,75,80`
44  - `cuda_version=([10.1])` contains the cuda version to be used for construct.
45  _PGI 19.10_ compilers only supports _cuda 9.2 10.0 and 10.1_ for OpenACC. To be consistent with the construct, we strongly recommend to use the same version of CUDA compiler as your OpenACC compiler.
46  - `opt=(debug|debug+|[release])` decides the optimization level of the compilation

48 ### Some targets
49 
50  - `create_build` ;
51  Used In association with BUILD_DIR will create a new build directory
52  with links to source files and _source/Makefile.pgi_. When BUILD_DIR is not specified, the default directory is `build/`. This target become useful when you want to keep object's files from a different build.
53 
54  @note Depending on the precision you might have to rebuild the `2decomp_fft` library.
55  e.g. `make create_build BUIL_DIR=../build-mix`
56 
57  - `2decomp_fft_rebuild` ;
58  This phony target allow you to rebuild 2decomp_fft library in double precision
59  Since the compilation uses the same directory for 2decomp_fft, you might want to
60  be sure that your library is being compiled into the correct precision
61 
62  - `2decomp_fft_rebuild_single` ;
63  Same as previous target but except from the precision's construct which happen here to in single. There is only two precision modes for 2decomp_fft Library. Tinker mixed precision building requires 2decomp_fft single precision library.
64 
65  - `thrust` ;
66  Build the wrapper on CUDA thrust library
67 
68  - `thrust_lib_rebuild` ;
69  [Re]Build the wrapper on CUDA thrust library
70 
71  - `plumed` ;
72  Build and Install Plumed Libraries required by Tinker-HP
73 
74  - `libtinker` builds `libtinker.a`
75 
76  - `all` *(default target)* ;
77  compile link and install `bin/analyze` `bin/bar` `bin/dynamic` and `bin/minimize`. If you just want one program to be build just enter `make <program>`.
78  e.g. `make analyze dynamic`
79 
80  - `[dynamic|analyze|minimize].mixed` ; deprecated
81  compiles link and install analyze|dynamic|minimize.mixed *(mixed precision)*. Those specific targets call behind `make` on their main target. Only used one at the time to avoid over building.
82  e.g. `make analyze.mixed -j4` is fine
83 
84  - `[dynamic|analyze|minimize].single` ; deprecated
85  compiles link and install analyze|dynamic|minimize.single *(full single precision executables)*.
86 
87  - `[dynamic|analyze|minimize].cpu` ; deprecated
88  compiles link and install analyze|dynamic|minimize.cpu. CPU binaries

91 ## Custom Build
92 Let suggest that we want CPU binaries in double precision combined with an out-of-source build by hand. After linking `source/Makefile.pgi` to `source/Makefile`, we should follow the next script for an out-of-source build :
93 
94 @code{.sh}
95 $> pwd
96 #> /home/$user/.../tinker-hp/GPU
97 $> mkdir -p bin
98 $> cd source
99 $> make arch=cpu 2decomp_fft_rebuild # build lib2decompfft.a
100 $> make thrust_lib_rebuild # build libwapper.a
101 $> make create_build BUILD_DIR=../build_CPU # create build directory
102 $> cd ../build_CPU
103 $> make arch=cpu all -j6 # build Tinker's program for CPU
104 $> ls ../bin # list binaries
105 #> analyze dynamic minimize bar pimd
106 @endcode
107 
108 or the following one for an in-source build:
109 
110 @code{.sh}
111 $> cd source
112 $> make arch=cpu prog_suffix=.cpu all -j4
113 $> ls ../bin
114 #> analyze.cpu dynamic.cpu minimize.cpu bar.cpu
115 @endcode
116 
117 You can also create a configuration bash file that store your configuration and run it with your desire targets.
118 
119 @code{.sh}
120 $> cat << EOF >Tconf.sh
121 #!/bin/bash
122 make FPA_SUPPORT=1 COLVARS_SUPPORT=1 prec=mixed arch=device compute_capability=60 cuda_version=11.3 prog_suffix=.gmix $@
123 EOF
124 $> chmod 740 Tconf.sh
125 $> cd source
126 $> ln -s ../Tconf.sh T
127 $> ./T 2decomp_fft_rebuild_single # Rebuild 2decomp_fft library in single precision
128 $> ./T -j8 # Build binaries (*.gfix) for 70 compute_capability device using fixed precision
129 @endcode
